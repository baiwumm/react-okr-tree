## 7. 未收口

一条，属「功能在、执行机制缺」：

| 缺口                                                                                            | 影响条目 | 补法                                                                                                      |
| ----------------------------------------------------------------------------------------------- | -------- | --------------------------------------------------------------------------------------------------------- |
| 「render 阶段不得调用会触发通知的方法」没有执行机制（只有 requirements R1 的书面约定 + review） | R1       | 自定义 ESLint 规则，或在 `src/model/notifier.ts` 加开发期运行期断言（「通知只允许在事件 / effect 里发」） |

这条路已经试过两条现成规则，都不成立，记下来免得再试一遍：

- `react-hooks/immutability`（`eslint-plugin-react-hooks@7` 的编译器规则）**抓得到** `node.expanded = x`，但它同时把
  `OkrTreeNode.tsx` 里合法的两处（OKR 左侧按钮切 `leftExpanded`、掉帧保护里改局部变量）判红——这套「可变 store」
  设计本来就要在事件回调里改对象，全局开会把设计本身判成错误，故不启用。
- `react-hooks/set-state-in-render` **抓不到**：它只认 `useState` 的 setter，外部 store 的通知（本包的
  `Notifier.notify()`）在它视野外——实测在组件体里插一句 `node.expanded = true`，该规则仍然全绿。
- React 自带的开发期告警也不够：同组件渲染中改外部 store，React 不报（实测 `console.error` / `warn` 零命中），
  只有跨组件 setState 才报。

另有两条**有意不做**：
与源项目 CSS 的逐字 diff（压缩器会合并同体规则，改为几何常量门禁）、24 个 Demo 与原页面的并排像素比对
（视觉基线拍的是 demo 块本身，交互由 `demo-interaction.spec.ts` 断言）。
